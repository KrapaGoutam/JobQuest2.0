# Phase 2.1-A Implementation Report

**Objective:**
Fix the Resume / Attached Document display so that JobQuest surfaces the manually entered resume/version label that is already stored by the capture pipeline.

**Verified Root Cause:**
The manual resume version `label` was successfully saved in the database during document capture (e.g., via `rpc_extension_capture`). However, the frontend UI/TypeScript definition for `ApplicationDocumentRecord` in `types/documents.ts` omitted the `label` property, causing the UI component `ApplicationDocumentsSection.tsx` to safely, but incorrectly, fall back to "Attached Document" rather than displaying the existing label.

**Branch:** `fix/2.1a-resume-version-visibility`
**Base Branch:** `development`

**Files Changed:**
- `apps/web/src/types/documents.ts`
- `apps/web/src/components/documents/ApplicationDocumentsSection.tsx`

**Behavior Before:**
The UI displayed `Attached Document` or just the `resume.name` because the `label` property was stripped by frontend typings.

**Behavior After:**
The UI correctly prioritizes displaying the stored `label` (if present) over `resume?.name`, defaulting to `Attached Document` as a last resort. 

**API Impact:**
None. The existing query payload already returned the column.

**Database Impact:**
None. Schema untouched.
