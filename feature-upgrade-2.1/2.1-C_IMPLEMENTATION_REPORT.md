# Phase 2.1-C Implementation Report

**Objective:**
Implement Application Grouping ("Group by Date") alongside the existing "Group by Month" in the Applications view, enabling day-level grouping (Today, Yesterday, formatted calendar date) while preserving existing filtering, sorting, pagination, and Month grouping semantics.

**Verified Current Grouping Architecture & Reuse:**
- **Grouping Architecture Reused:** The existing application grouping pattern in `ApplicationsTable.tsx` and `applicationProductivity.ts` groups the currently paginated/filtered result set on the client. `ApplicationsTable` iterates through computed groups to render group headings above table rows (desktop) or card list sections (mobile).
- **Date Field Used:** `created_at` (Date Added) is the primary semantic date driving application listing, date filtering (`dateAddedFrom`/`dateAddedTo`), and existing Month grouping (`groupApplicationsByMonth`). `getApplicationGroupingDate` prefers `created_at` (with graceful fallback to `applied_at` if `created_at` is omitted) to maintain 100% coherence with the displayed "Date Added" column and existing monthly grouping.
- **Missing-Date Behavior:** Applications with missing, null, empty, or unparseable dates are safely assigned to group key `'undated'` with label `'No application date'`, positioned deterministically at the end of the group list without throwing runtime errors.
- **Filter / Sort Interaction:** Grouping operates strictly on the active paginated and filtered application records returned by `fetchApplications`. Intra-group record ordering is strictly preserved from the active user sort. Day groups are ordered by day key matching the sort direction when sorted by date (`created_at` or `applied_at`), and descending by default.
- **Grouping Options:** The toolbar control is extended to support a mutually exclusive group:
  - `None` (flat list)
  - `Date` (Group by date)
  - `Month` (Group by month)
  Clicking the active group button toggles it back to `None`.

**Timezone Behavior:**
- Leverages the user's profile timezone (`timeZone`) provided by `useProfileTimeZone`.
- Date grouping uses `dayKey(date, timeZone)` to determine the stable calendar day key (`YYYY-MM-DD`).
- Compares against `dayKey(now, timeZone)` for "Today" and `previousDayKey(todayKey)` for "Yesterday", preventing local browser timezone drift and midnight boundary skew.

- **Scenario C (Group by Month):** Click "Group by month". Existing month-based groupings ("Month Year") render as expected.
- **Scenario D (None):** Clicking an active group button deactivates it back to None, displaying the canonical flat table/card list.
- **Scenario E (Filtering & Search):** Applying search query or stage/outcome/aging filters while grouped maintains active filtering without resurrecting filtered records.
- **Scenario F (Sorting):** Changing sort order between ascending and descending re-orders day groups coherently while preserving intra-group sorting.
- **Scenario G (Missing Dates):** Applications with absent or unparseable dates display safely in a trailing "No application date" group.
