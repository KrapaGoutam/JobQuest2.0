# Phase 2.1-F Implementation Report

**Objective:**
Implement JobQuest 2.1-F Analytics Goal Trends capability so that configured application goals, daily actual submissions, completion percentages, historical target-vs-actual trends, and high-value summary metrics (days reached, success rate, daily average, and streak) are visible, actionable, and interpretable in Analytics.

**Branch:** `feature/2.1f-analytics-goal-trends`  
**Base Development SHA:** `cda70cf4e282856ae6028b484747f72eb2cc8f97`

---

## 1. Verified Data Flow & Existing Backend Architecture

- **Goal Storage & Versions:** Stored in `public.goals` with unique constraint `uq_goals_user_type_effective (workspace_id, user_id, goal_type, effective_date)`.
- **Backend RPCs Reused:**
  - `rpc_set_goal_for_user`: Inserts/updates effective-dated goals. Past closed periods are immutable (`GOAL_HISTORY_IMMUTABLE`).
  - `rpc_get_goal_progress`: Generates historical period windows partitioned by goal type and bounded by effective dates (`[v.effective_date, least(next_effective - 1, v_today)]`), measuring actual applications in the user's timezone via `app.goal_actual`.
  - `rpc_get_analytics_overview`: Overview metrics, weekly pacing, and pipeline breakdowns.
- **Frontend API & Normalization:**
  - `fetchGoalProgress` in `apps/web/src/api/analytics.ts` called with `periodCount: 36` to retrieve up to the full 36 periods supported by the backend without N+1 queries.
  - Zero new RPCs or database endpoints created; 100% reuse of verified existing backend infrastructure.

---

## 2. Critical Historical Goal Semantics

- **Audit Findings:** The existing database and `rpc_get_goal_progress` already preserve historical targets per effective period window.
- When a user changes their daily goal (e.g. from 10 to 15 on October 6):
  - Periods prior to October 6 retain their original target of 10.
  - Periods from October 6 forward receive the new target of 15.
  - Historical periods are never retroactively overwritten with today's target.
- Days without a configured goal retain `target: null` and `status: 'NO_GOAL'` without fabricating false targets.

---

## 3. Timezone Semantics

- Aligns directly with profile timezone (`progress.timezone` / `useProfileTimeZone`) established during Phase 2.1-B.
- Backend `app.goal_actual` measures between `p_period_start::timestamp at time zone p_timezone` and `p_period_end::timestamp at time zone p_timezone`.
- Frontend uses `dayKey(iso, timeZone)` and `previousDayKey(key)` from `apps/web/src/lib/time.ts` to ensure calendar day boundaries on the Dashboard and in Analytics match identically.

---

## 4. Date Range & Controls

- Respects the selected Analytics date range (`30d`, `90d`, `180d`, `1y`) passed from `AnalyticsView` toolbar to `GoalsTab`.
- History points and metrics filter to the active date bounds while preserving all chronological periods.

## 5. Analytics Metrics & Summary KPIs

Four high-value summary metrics implemented via `.analytics-kpis.analytics-kpis-4`:
1. **Goal Reached:** Total days meeting or exceeding target (e.g. `12 of 20 days`).
2. **Success Rate:** Percentage of eligible goal days reached (`daysReached / totalEligibleDays * 100`). Days without a configured goal are strictly excluded from the denominator.
3. **Average Daily Applications:** Mean applications submitted per active day/period (e.g. `8.4 / day`).
4. **Current Streak:** Consecutive eligible days where `actual >= target`. If the current in-progress day has not yet reached the target, it does not prematurely break an existing streak from yesterday; once reached, it is counted. Days without a configured goal do not break the streak.

## 6. Primary Goal Trend Visualization

- **Component:** `GoalTrendChart` in `apps/web/src/components/analytics/AnalyticsCharts.tsx`.
- **Design:** Vector SVG matching JobQuest's chart design system (`viewBox="0 0 660 190"`):
  - **Actual Applications:** Column bars styled with `--chart-1` and distinct fill/pattern. Bars that meet or exceed target are styled with `--color-success` accent.
  - **Daily Goal Target:** Dashed step line (`.pace-goal-line`) connecting consecutive days with configured goals, with target indicator dots.
  - **Missing Targets:** Days without goals display actual applications without fabricating target lines or markers.
  - **Uncapped Percentages:** Completion percentage retains true value (e.g. `13 / 10 = 130%`).
  - **Tooltips & Labels:** Accessible `<title>` on SVG groups with full details (`Oct 2: 12 submitted · Target 10 (120% · Met)`).
  - **Screen Reader Support:** Full hidden `<table>` (`.sr-only`) containing Date, Applications, Target, Completion Rate, and Status.
  - **Responsive:** Scales fluidly on mobile and desktop without horizontal scroll.

---

## 7. Empty & Edge States

- **No Goals Configured:** Informative card explaining that goal analytics will begin tracking once an application goal is set, with an "Add goal" CTA.
- **Goals Configured with 0 Applications:** Displays legitimate 0 actuals and 0% completion without hiding valid data.
- **Historical Gaps:** Gaps without goals are marked `NO_GOAL` without falsifying success/failure.
