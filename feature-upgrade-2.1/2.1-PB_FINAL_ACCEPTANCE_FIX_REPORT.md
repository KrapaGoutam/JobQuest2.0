## D — Tasks & Follow-ups

- **Cancel vs Dismiss Finding**: User-facing "Cancel" terminology was ambiguous and created uncertainty around task lifecycle and recurrence. Aligned all UI surfaces (`QueueRow.tsx`, `TaskDetailPanel.tsx`, and confirmation dialogs) to use "Dismiss".
- **No Next Action Semantics**: Traced and verified that "No next action needed" remains strictly separate from task dismissal. It invokes `rpc_complete_next_action(id, null, null)` to clear or update next-action metadata on the `applications` table, without touching task rows.
- **Recurring Dismiss Behavior**: Dismissing a recurring task sets its status to `CANCELLED` via `rpc_cancel_task`. In JobQuest's architecture, recurring occurrences are generated only upon task completion (`rpc_complete_task`). Thus, dismissing a task cleanly terminates the recurrence chain without requiring database or RPC changes.
- **Bulk Dismiss Behavior**: Updated `TasksView.tsx` toast messaging to clearly differentiate successful dismissals from failures in standard format (`X dismissed • Y failed`). Select All / Deselect All behavior remains intact.
- **API / RPC Reused**: Reused existing canonical `rpc_cancel_task` and `rpc_complete_next_action`. Zero database modifications or migrations.

## F — Job Capture / Copy JSON

- **Original Root Cause**: First-successful-extractor pattern caused premature termination when partial metadata was captured, missing detailed DOM sections. In addition, "Copy JSON" previously required saving to produce a complete record.
- **Implemented Extraction Order**: Rewrote the extraction pipeline in `apps/extension/extractors/index.js` into an explicit 6-tier field-by-field merge cascade:
  1. Site adapter (Greenhouse, Lever, Indeed, LinkedIn, HiringCafe, Dice)
  2. Embedded app state (`__NEXT_DATA__` bounded traversal)
  3. JSON-LD (`schema.org/JobPosting` with graph support)
  4. DOM sections (anchored by heading/strong/label heuristics)
  5. Generic enhanced extraction
  6. Original extractor fallback
- **Original Extractor Fallback**: Preserved the original generic extractor as the final fallback layer; existing heuristics remain active.
- **LinkedIn Adapter (`apps/extension/extractors/linkedin.js`)**: Scoped strictly to the job detail pane (`[data-sdui-screen="SemanticJobDetails"]`, `.jobs-details__main-content`). Excludes page `h1`, personal JobMatch insights, connections, and extension-injected elements.
- **HiringCafe Adapter (`apps/extension/extractors/hiringcafe.js`)**: Leverages `__NEXT_DATA__` with job ID route validation, falling back to `#job-info` and `#job-description` in the DOM or open dialog.
- **Dice Adapter (`apps/extension/extractors/dice.js`)**: Scoped to `job-detail-header-card`, extracting clean title, company, location, remote/onsite badges, employment type, and deduplicated skills.
- **Generic Enhanced Extraction**: Safely traverses embedded app state (`__NEXT_DATA__`) with a recursion depth bound of 8. Categorizes unknown DOM sections into an `extras` dictionary rather than dropping them.
- **Stale SPA Protection**: In `jsonld.js` and app-state traversal, candidate structured data is verified against the active page URL/pane job identifier. If a mismatch is detected without a corresponding match, the stale data is rejected.
- **Schema 1.1**: Upgraded AI Job JSON schema to `1.1` in `apps/extension/serializers/ai-job-json.js`. Added `extras` mapping and omitted internal `raw_payload`.
- **Pre-save Copy JSON**: Evaluates the live unsaved form state (`currentData`) immediately, allowing users to copy sanitized AI-ready JSON directly from the screen before saving.
- **Pre-save Independence**:
  - Save required: NO
  - Application ID required: NO
  - Existing record required: NO
- **Security & Privacy Exclusions**: Stripped tokens, secrets, sessions, personal user accounts, and LinkedIn connection/match data from serializers and embedded traversals.
- **Database / Migrations**: NONE (0 migrations).
