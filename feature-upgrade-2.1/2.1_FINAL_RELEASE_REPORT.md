## Cumulative Scope Summary (Phases 2.1-A through 2.1-F)

### Phase 2.1-A: Resume Version Visibility
- Added `label` to `ApplicationDocumentRecord` typing and prioritized `item.label` over `resume.name` in `ApplicationDocumentsSection.tsx`, falling back safely to "Attached Document" only when no label exists.

### Phase 2.1-B: Dashboard Goal + Daily Metrics
- Introduced SearchPulse Daily Goal Card and enhanced GoalProgress widget.
- Added daily metric comparisons (today vs yesterday, configured goal, percentage, remaining count) via `calculateDailyGoalMetrics`.
- Enclosed Today's Work queue in a contained scroll container (`max-h-[460px]`) with sticky header for viewport stability.

### Phase 2.1-C: Application Grouping
- Added Day-level grouping ("Group by Date") alongside "Group by Month" in Applications table.
- Extended toolbar with mutually exclusive grouping selector (None, Date, Month).
- Implemented `groupApplicationsByDate`, `getApplicationGroupingDate`, and hardened missing-date fallbacks without disturbing pagination, sort, or filtering.

### Phase 2.1-D: Tasks & Follow-ups
- Added single-task "Dismiss" action and bulk selection / bulk Dismiss capabilities.
- Implemented recurrence stop upon dismissal for recurring tasks.
- Refined queue row CSS grid layout for seamless checkbox integration and responsive behavior.

### Phase 2.1-E: Extension Capture + AI Job JSON
- Added generic HTML fallback extractor to browser extension for arbitrary job board capture.
- Added `serializeAiJobJson` in extension and web application (`lib/aiJobJson.ts`).
- Added "Copy Job JSON" action to both extension sidepanel and web `ApplicationDetailDrawer` without exposing internal database IDs or secrets.

### Phase 2.1-F: Analytics Goal Trends
- Added `GoalTrendChart` vector visualization with Target vs Actual series and uncapped overachievement percentages.
- Added 4 high-value summary cards: Goal Reached, Success Rate, Average Daily, and Current Streak via `calculateGoalTrends`.
- Connected date range filtering (`30d`, `90d`, `180d`, `1y`) honoring profile timezone semantics.
