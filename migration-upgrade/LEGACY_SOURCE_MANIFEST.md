# Legacy Source Manifest

The most important JobQuest 1.0 source files a future implementation agent will
need to consult directly, beyond what this documentation package already
summarizes. Documentation coverage: **COMPLETE** (this package fully documents its
behavior — consult only for exact syntax), **PARTIAL** (this package covers the
important parts; consult for edge cases), **REFERENCE RECOMMENDED** (this package
describes it at a high level; read the file itself before implementing anything
touching it).

| Path | Purpose | Features supported | Business logic contained | Why it may be required | Coverage |
|---|---|---|---|---|---|
| `backend/src/server.js` | Main HTTP router, auth routes, static file serving | Auth, Applications CRUD, generic trackers, dashboard, manager routes | Route dispatch order (see the dead-code overlap noted in `API_INVENTORY.md`), CSP headers, static-file security | Exact request/response shapes, header logic | PARTIAL |
| `backend/src/service.js` | Core validation, application CRUD, import/duplicate logic, `STAGES`/`PRIORITIES`/etc. constants | Applications, Import, canonical enums | `validateApplication`, `changeStage` (thin variant), `duplicate()`, alias table | This is the single source of truth for every enum and most validation rules | REFERENCE RECOMMENDED |
| `backend/src/advanced.js` | Timeline, checklist, tags, saved views, resumes-analytics, reminders, goals, calendar, exports, analytics, manager audit | Most "secondary" domains | `rates()` formula, aging bands, stage-duration stats, CSV export dispatch | Largest single file (~1672 lines) — highest density of business rules not yet exhaustively unit-tested in this documentation pass | REFERENCE RECOMMENDED |
| `backend/src/feature-upgrade.js` | Rich stage-change transaction, query/kanban engine, XLSX export, resume clone/history/compare, navigation preferences, goal progress-series | Applications query/Kanban, Resumes revisions, Exports | `changeStage` (rich, winning variant), `buildApplicationWhere`, `safeCell()` | Contains the *actual* stage-change behavior (the `server.js` variant is dead) — critical not to miss | REFERENCE RECOMMENDED |
