## 3. Database & Query Performance

### 3.1 Global Search (`rpc_global_search`)
- Query type: Multi-domain `UNION ALL` across `applications` (joined with `job_snapshots`), `contacts`, `journal_entries`, `interviews`, and `documents`.
- Indexes utilized:
  - `idx_applications_workspace_id` (B-tree)
  - `idx_job_snapshots_search_gin` (GIN trigram / full-text index on `job_title`, `company_name`, `job_description`)
  - `idx_journal_entries_workspace_id` (B-tree)
  - `idx_contacts_workspace_id` (B-tree)
- Measured Latency:
  - Cold query execution: **21ms**
  - Warm cached execution: **8ms - 14ms**
  - All executions well below the 100ms perceptual responsiveness threshold.

### 3.2 Row-Level Security (RLS) Overhead
- All queries evaluate tenant membership via `auth.uid()` and workspace membership cached in session claims.
- Subquery evaluation overhead: **< 1.5ms** additional query execution time compared to non-RLS execution.
